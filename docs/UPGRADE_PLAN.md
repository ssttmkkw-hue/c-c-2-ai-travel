# 画质升级说明与后续建议（fable/upgrade 分支）

> 写给 kk。前两节尽量不用术语；第 3 节是给 Claude 审阅用的；第 4 节是接下来可以做什么。
> 范围：提交 `83fd3ad..8015d76`（共 8 个提交，40 个文件，+1985 / −120 行）。
> 技术细节的完整版在 [`UPGRADE_NOTES_FOR_CLAUDE.md`](UPGRADE_NOTES_FOR_CLAUDE.md)，这里不重复。

## 0. 一句话总结

**之前糊，是因为游戏只画了屏幕十六分之一的像素再硬拉大；现在按屏幕真实像素画、只做整数倍放大，默认清晰度是原来的 4 倍（Retina 上约 7 倍），同时把一帧里的绘制次数从约 700 降到约 100，并补了天空、调色、地面细节和飘落粒子。**

有一件事没做到，先说在前面：**所有验证都在没有显卡的机器上完成，真实电脑和手机上的帧率还没测过**（见 2.9 和第 5 节）。

## 1. 为什么之前糊

可以把游戏画面想成一张马赛克拼图：格子越少、越大，画面越粗。原来的问题有四层，前三层是「格子」本身的问题，第四层是「线条和影子在大格子下坏掉」。

### 1.1 格子太少：只画了窗口的 1/4 × 1/4

原来的做法（旧 `src/core/Engine.ts` 的 `resize()`）是：窗口宽高各除以 `pixelSize`（默认 4），按这个小尺寸画，再让浏览器拉伸到全屏。

| 窗口 | 实际画的像素 | 相当于 |
|---|---|---|
| 1280×800 | 320×200 | 上世纪 90 年代初 DOS 游戏的分辨率 |
| 1920×1080 | 480×270 | 屏幕像素的 1/16 |

角色身高 1.2 米，在这个分辨率下脸只有十几个格子，五官、招牌、远处建筑都挤成色块。「像素风」需要低分辨率，但这个数字低过头了。

### 1.2 格子大小不均：放大倍数不是整数

旧代码用 `Math.ceil(窗口宽 / 4)` 取整，再由浏览器把画面拉回 100% 宽。

- 窗口宽高恰好是 4 的倍数时（比如正好 1280×800、1920×1080）没问题。
- 其他尺寸就不是整数倍了。例如 1366×768 会画成 342×192，横向放大 3.994 倍：大部分格子 4 像素宽，隔一段出现一个 3 像素宽的。实际使用中浏览器窗口很少恰好是 4 的倍数（有地址栏、可以随意拖动），所以**多数情况下都中招**。
- 观感就是：静止时线条粗细不一，镜头一动，细节会「抖」。
- 另外旧 `src/ui/base.css` 里 `image-rendering: pixelated` 后面又写了一行 `crisp-edges`，在部分浏览器里后一行会盖掉前一行，放大方式不受控。

### 1.3 没考虑高分屏：Retina / 系统缩放下更粗

旧代码写死 `renderer.setPixelRatio(1)`，也就是完全不看 `devicePixelRatio`（屏幕实际像素与「逻辑像素」的比值）。

- MacBook Retina（比值 2）：一格 = 8×8 个真实像素。同样是 1280×800 的窗口，屏幕其实有 2560×1600 个像素，游戏仍然只画 320×200，只用了 1/64。
- Windows 125% / 150% 缩放：一格 = 5 / 6 个真实像素，同理更粗。

所以同一个游戏，屏幕越好反而看起来越糊。

### 1.4 线条和影子在大格子下坏掉

- **描边断成虚线**。旧的描边是把物体复制一份、整体放大一点涂黑（旧 `src/render/toon.ts`，厚度固定 0.04 米）。近处很粗；稍远一点厚度不足一个格子，就时有时无，变成虚线。细长的东西（电线、栏杆）侧面几乎没有描边。
- **影子有锯齿和条纹**。整张地图（120 米见方）共用一张 2048 的阴影图，一个阴影像素约 6 厘米，而且是不做平滑的硬采样（`BasicShadowMap`），影子边缘呈梳齿状。背光的面（树冠背面、斜屋顶）还会出现一条条的杂纹，这是阴影算法的经典毛病，旧代码靠加大偏移硬压，没压干净。
- **界面文字发糊**。界面用的是 12 像素的点阵字，在 125% / 150% 缩放下每个字的像素落不到整数位置；对话正文用了 14px（不是 12 的整数倍），本身就对不齐。

### 2.1 渲染管线：先画到「内部画布」，再整数倍放大

提交 `83fd3ad`。`src/core/Engine.ts`、`src/render/quality.ts`（新）。

- 屏幕上的画布现在和**屏幕真实像素**一一对应，浏览器不再做任何拉伸。
- 场景先画到一张看不见的内部画布，再由我们自己放大到屏幕：
  - **像素风**（默认）：放大倍数一定是整数（2、3、4…），每个格子严格一样大。倍数按「画面短边想要多少格」算（复古 270 / 标准 360 / 精细 540），所以普通屏、Retina、4K 上看到的颗粒感一致。
  - **高清**：不放大，按屏幕像素直接画，并开抗锯齿。给不喜欢像素风的人用。
- 画面先以线性亮度计算，最后统一转成显示器的颜色（半透明混合比以前更正确，半透明物体略微变亮）。

### 2.2 画质设置

提交 `83fd3ad`。`src/core/settings.ts`、`src/ui/settings/**`。

原来的「像素大小」滑块换成三组单选：

| 设置项 | 选项 | 作用 |
|---|---|---|
| 画面风格 | 像素风 / 高清 | 见 2.1 |
| 像素颗粒（仅像素风） | 复古 / 标准 / 精细 | 短边 270 / 360 / 540 格 |
| 画质 | 低 / 中 / 高 | 阴影图 1024 / 2048 / 4096，高清模式的抗锯齿 0 / 2 / 4 倍，粒子 关 / 减半 / 全开 |

- 默认值按设备定：电脑 = 精细 + 高；触屏设备 = 标准 + 中；CPU 核数或内存 ≤ 4 的弱机器 = 低。
- 面板底部有一行「当前渲染 960×540 · 每格 2×2 屏幕像素」，方便确认。
- 旧存档能读。旧的默认值 4 不沿用（它就是糊的来源）。

### 2.3 UI 缩放

提交 `eb4b25a`。`src/ui/scale.ts`（新）。

- 整个界面按「整数 ÷ 屏幕缩放比」缩放，12 像素点阵字永远落在整数个真实像素上，125% / 150% 缩放下也清晰。
- 大屏自动放大：1080p 界面 ×2，4K ×4，不会出现小字。
- 对话正文 14px → 12px；NPC 头顶气泡的位置跟着换算。

### 2.4 描边与阴影

提交 `83fd3ad`、`784e7b7`。`src/render/toon.ts`、`src/world/World.ts`。

- **描边粗细在屏幕上恒定**：像素风下永远是 1 格，高清下按分辨率折算（1080p 约 2.4 像素，最少 1.5），远近一致，不再断成虚线。细长物体四周一样粗。
- **影子**：中 / 高画质先做平滑；像素风再把平滑结果一刀切成硬边，得到「轮廓圆滑的硬影子」，高清保留柔边。背光面的条纹用「按表面倾斜程度加大偏移」的办法消掉了。
- 美术上补了两处：东京电线打开描边；吉萨金字塔最底层原来悬空约 6 厘米，底下一圈细影子在像素风下是一排虚线，已落地。

### 2.5 静态合批（性能）

提交 `e6cdbac`。`src/render/batch.ts`（新）、`src/art/kit.ts`、`src/avatar/chibi.ts`。

通俗说：原来每个零件（一块木板、一片屋檐）都要单独通知显卡画一次，外加它的描边再画一次。现在地图建好后，把所有不会动的零件按类别焊成几大块，一次画完。

| 地图 | 零件数（mesh） | 每帧绘制次数（draw call，1280×800 出生点） |
|---|---|---|
| 东京 | 942 → 171 | 约 700 → 约 125 |
| 吉萨 | 677 → 93 | 约 455 → 约 86 |
| 巴黎 | 927 → 128 | 约 735 → 约 124 |

- 会动的东西（摇晃的灯笼、闪烁的招牌、骆驼头、鸽子）用 `kit.dynamic(obj)` 标记，不参与合并。忘了标的话，加载时有一个自动检测兜底，并在开发模式下警告。
- 角色按关节合并，每个角色从约 50 次降到约 25 次。换装时先拆开、换完再合。
- 剩下的约 100 次里，大头是 4 个角色（各约 25 次）。

### 2.6 天空、调色、调色板新字段

提交 `eacde8d`。`src/render/sky.ts`（新）、`src/core/Engine.ts`、`src/render/palette.ts`。

- **天空**：纯色背景换成渐变穹顶，地平线和雾同色，往上过渡到天顶色，朝太阳方向有光晕和太阳圆盘。像素风下切成 14 条色带，高清下平滑。
- **调色**：最后输出前做三步：曝光 → 高光柔和压缩（太亮的地方不再直接过曝成一片白）→ 饱和度（默认 1.15，略鲜艳）。没有用常见的电影感调色曲线，因为它们会改变调色板颜色的色相，和「颜色只来自调色板」的规则冲突。
- **调色板新增 4 个可选字段**：`skyTop`（天顶色）、`sunDirection`（太阳方向）、`exposure`（曝光）、`saturation`（饱和度）。老调色板不用改。
- 三张图各自调了：东京太阳低、影子长，吉萨太阳高；雾的起止距离拉远约 10~15%，远景更通透。

### 2.7 地面细节与路缘

提交 `8ac628e`。`src/art/props/ground.ts`（新）、`kit.instances`。

- 地面原来是一整块纯色。现在加了铺装色块 / 沙纹、草丛、石子，会避开道路和建筑。
- 用「实例化」实现：成百上千个同样的小东西只算 1 次绘制。
- 三张图各加了路缘石，路和地面之间有了明确的边界。

### 2.8 T11 飘落粒子（轻量版）

提交 `8ac628e`。`src/fx/particles.ts`（新）。

- 东京樱花瓣 260 个、吉萨沙尘 220 个（横向飘）、巴黎落叶 90 个。只在玩家周围循环，1 次绘制。
- 画质「低」关闭，「中」减半。贴到镜头前的粒子会缩小消失，不会挡视线。
- **T11 没做完**：远景云（`src/fx/clouds.ts`）没做；粒子是小方块，不是真的花瓣 / 叶子形状。

**关于 fps，请不要拿这一列下结论**：

- 测试机**没有显卡**，用的是 swiftshader（CPU 模拟显卡）。真实显卡上的帧率会高很多（具体多少没测），瓶颈也完全不同。
- 测试时机器同时在跑别的任务（8 核，负载 16），读数噪声很大。第一轮结束时同一脚本量到 1280×800 是 18~22，第二轮期间读数在 8~28 之间乱跳，这次是 9.5~13；1920 反而比 1280 高，本身就说明这列数字不可靠。
- **没有量过改前在同一环境下的 fps**，所以没有前后帧率对比。
- 第二轮另外做过一次更稳的测量（连续渲染 12 帧，取 8 组里最快的一组）：合批前后每帧约 41 / 35 / 43 毫秒 → 45 / 44 / 42 毫秒，**在软件渲染下合批没有带来可测的改善**。软件渲染的瓶颈是填像素和阴影（阴影约占四成），不是绘制次数。绘制次数降 6 倍的好处要在真实显卡、尤其手机上才看得到，**这一点没有验证**。

### 3.2 接口变化

**破坏性**

1. `Settings.pixelSize` 删除。改用 `renderMode` / `pixelDensity` / `quality`。仓库内的使用方（`ui/debugHud.ts`、`ui/settings`）已改。存储 key 不变，旧存档里的 `pixelSize` 只在 ≤2（→ 精细）或 ≥6（→ 复古）时迁移。
2. `addOutline(mesh, thickness)` 去掉第二个参数。仓库内原本没有调用方传它。粗细改由 `setOutlineWidth(px, renderHeight, fovDeg)` 全局控制（Engine 调用）。
3. `engine.renderer.domElement.width / height` 现在是**物理像素**，不再是内部分辨率。要内部分辨率读 `engine.view.width / height`。任何按画布尺寸做拾取、截图、后期的代码都要注意。
4. **合批后零件会从场景树里摘掉**（原来的 Group 还在，但是空的）。地图卡里拿着零件引用、`build` 之后还想改它的，必须 `kit.dynamic(obj)`。这是新的隐式约定，已写进 `MAP_CARD_SPEC.md`。
5. `renderer.shadowMap.type` 现在由 World 按画质切换（中 / 高 `PCFSoftShadowMap`，低 `BasicShadowMap`），别处不要再设。
6. `scene.background` 现在是雾色（兜底），真正的天空是挂在 `engine.scene` 上的 `__sky` mesh。

**新增**

- `engine.view: RenderView`、`engine.setGrade(exposure, saturation)`、事件 `render:view`（`Engine.start()` 时补发一次）
- `toon.ts`：`setOutlineWidth`、`setShadowTuning`、`refreshToonMaterials`、`outlineShell`、`isOutlineShell`、`ensureOutlineNormals`、`OUTLINE_ATTR`、`ToonOptions.vertexColors`
- `kit.dynamic(obj)`、`kit.instances(template, items, { shadow? })`
- `Palette.skyTop / sunDirection / exposure / saturation`
- `settings.ts` 导出类型和枚举数组（`RENDER_MODES` 等）

- `fx/particles.ts` → `core/settings`、`render/batch`

### 3.3 脆弱点

1. **阴影补丁依赖 three r170 的源码原文**。`toon.ts` 对 three 内置着色器块 `lights_fragment_begin` 里平行光那一行做字符串替换（常量 `SHADOW_CALL`）。`package.json` 写的是 `^0.170.0`，`npm install` 可能装到更新的小版本。对不上时不会报错，只在开发模式 `console.warn`，效果退回「没打补丁」（背光面条纹会回来，像素风的硬边影子变成硬采样）。建议合并时把版本锁死（见 4 节 P0-3）。
2. **`probeDynamic` 用 4 个假时间点试跑地图卡的 `onUpdate`**。现有回调都是时间的纯函数，没影响；以后写「累加 dt」的回调，加载时会多走 4/60 秒。
3. **UI 缩放用 CSS `zoom`**。Chrome / Safari 一直支持，Firefox 126 起支持。老 Firefox 不缩放，功能正常但字在非整数缩放下仍会糊。
4. **粒子用 `mesh.onBeforeRender` 读相机位置**，因为 `MapBuildContext` 没有相机。更干净的做法是给 ctx 加 `getCameraPosition()`。
5. **调试 / 模拟 DPR 时** Chromium 的 `device-pixel-content-box` 报值不乘 DPR，Engine 里有「偏差大于 1 像素就不信它」的保护；真机不受影响。

### 3.4 合并回 claude 分支的注意事项

分叉点是 `55ea968`（T09）。`claude/happy-curie-wrcwtq` 目前就停在这个提交，`main` 更早，本分支是它们的直接后继，**现在合并是快进，没有冲突**。之后如果 claude 分支先动了下面这些文件，才需要手工处理：

1. **`Engine.ts`、`toon.ts`、`World.ts` 改动面大**，如果 claude 分支也改了它们（比如看板上的「后期效果管线」「泛光」），建议以本分支的版本为底，把那边的改动重新叠上来，不要逐行合并。后期效果可以直接插在 Engine 第 2 步的着色器前后，RenderTarget 已经有了。
2. **claude 分支上新写的代码要查这几样**：读 `getSettings().pixelSize` 的；给 `addOutline` 传第二个参数的；把 `domElement.width` 当内部分辨率用的；`build` 之后还去改零件但没标 `kit.dynamic` 的；自己设 `shadowMap.type` 或 `scene.background` 的。
3. **新地图卡 / 新道具**：会动的要 `kit.dynamic`；调色板可以选填 4 个新字段；不需要再保证「几何体以自身中心为原点」（旧描边的限制，已取消）。
4. **看板上 Claude 保留任务的重叠**：「后期效果管线（边缘检测描边）」与本次的描边方案是二选一的关系；「泛光」需要的线性 HDR 缓冲已经具备（半浮点 RenderTarget），但现在的高光压缩在泛光之前，接入时要调整顺序。
5. **任务看板**：`tasks/T11-ambient-fx.md` 头部状态是 `review`，但 `tasks/README.md` 表里仍是 `todo`（README 是保留区，本分支没有同步）。合并时请顺手对齐，并决定 T11 是按「轻量版」验收还是拆出一张云的新卡。
6. **合并后的验收**：`npm run build`；`node /workspace/pwtool/fableshots.mjs <前缀>` 看控制台错误为 0、三张图 draw call 在 85~125 左右；开发模式控制台没有「未标记动态物体」和「阴影补丁没有生效」两条警告。

## 5. 已知问题与风险

### 没有验证的

1. **真实显卡和手机上没有跑过**。所有截图和数字来自 headless Chromium + swiftshader。高清 + 高画质在 4K 集显上的帧率、手机上的表现、手机默认档位是否合适，全部未知。
2. **合批的性能收益没有被测量证实**。draw call 确实降了 6 倍，但软件渲染下帧时间没变；真机上的收益是按经验的预期。
3. **没有改前的 fps 基线**，所以无法给出「帧率提升了多少」。
4. 浏览器只测了 Chromium。Safari、Firefox 没测（Firefox 126 之前不支持 UI 缩放用的 CSS `zoom`）。

### 画面上的

5. 比阴影图 1~2 个像素还细的物体（细绳、细杆），影子仍会断续，巴黎右侧地面能看到一条。改前也有。对应 P1-1。
6. 像素风下镜头移动时有「像素爬行」，是低分辨率 3D 的固有现象，没处理。对应 P2-2。
7. 所有画面都过了高光压缩曲线：亮度超过 0.8 的颜色比以前略暗、略偏白。调色板里很亮的颜色会和设计稿有细微出入。
8. 半透明物体因为改在线性空间混合，比以前略亮。
9. 半透明的静态物体（橱窗玻璃）合并后，彼此之间不再按远近排序。目前没看到问题，玻璃叠玻璃的场景可能出错。
10. 地面色块是离地 6 毫米的薄片，极远处（80 米外）理论上可能和地面闪烁，那里已经在雾里。
11. 巴黎清晨配金色落叶是按任务卡写的，季节感是否合适需要美术判断。
12. 界面里的 emoji 走系统字体，不是点阵风格。

### 代码上的

13. 阴影补丁依赖 three r170 源码原文，版本没有锁死（3.3 第 1 条）。
14. 合批是隐式约定：`build` 之后零件被摘掉，忘了标 `kit.dynamic` 的动画会静止。有自动检测兜底，但只能抓到「每帧都在动」的，事件触发的动画（比如点一下才开的门）抓不到。
15. 角色合批后，`setOutfit` 之外直接改零件材质的代码不会生效。目前没有这样的代码。
16. 不支持浮点颜色缓冲的老设备退回 8 位，暗部可能有轻微色带。
17. `passport.css` 的 `@media (max-width: 720px)` 按视口宽度判断，和 UI 缩放后的布局宽度在个别窗口尺寸下不一致，只影响单列 / 双列的切换点。
18. 主包 568KB，超过 vite 的 500KB 提示线。对应 P1-7。
19. T11 状态在任务卡（`review`）和看板（`todo`）之间不一致，云没做（3.4 第 5 条）。
20. `fableshots.mjs` 和几个临时测量脚本不在仓库里（`/workspace/pwtool`、`/tmp`），换机器就没了。对应 P0-5。
